# Consolidated findings ledger: Find architecture spine

## How this ledger was built

- **Original IDs:** Input Check = `F1`–`F20`, Rubric = `R1`–`R10`, Adversarial = `A1`–`A15`, Tech-currency = `#1`–`#22`. Every finding already had an ID, so no `<Review>-n` IDs were assigned.
- **Tech-currency scope:** of its 22 items, 14 are "confirmed" with no defect. They are not counted as findings, except #10, #11, and #13, which are confirmed but carry advice. The ledger counts those three as Low. The ledger also assigned severities to the two "unverified" items, which had none: #20 is Medium, because spike S8 gates it, and #21 is Low.
- **Merging:** duplicates were merged, and a merged row takes the highest severity of its originals: R1 + #2; R2 + A13; R3 + A7; R4 + A3 + A4; R10 + #15; F16 + #11.
- **Status rule (strict):** **Applied** means the current spine or PRD text clearly resolves the issue. **Partially applied** names what is missing. **Not applied** means no relevant change was made. **Deferred** has a stated reason.
- **Required before approval:** "Yes" means the spine shouldn't be approved while this row is unresolved. It doesn't mean the row is still open.

### Observations not raised by any review (not counted)

- **O-1 (relates to CF-04 and CF-11):** in the S3 worker fallback, AD-9 requires `selectFolder()` to call `FolderPicker.pick()` before any `await`. A proxy that forwards `selectFolder` to a worker would lose user activation, and `showDirectoryPicker` isn't available in workers. The fallback would therefore need the proxy to call the picker on the main thread and pass the `DirectoryRef` to the worker. Spike S1, which verified that a handle works in a worker, is retired. Suggested fix: add one clause to the AD-5 fallback: "the proxy calls `FolderPicker.pick()` on the main thread and transfers the `DirectoryRef`; verify the grant carries over if S3 fails."
